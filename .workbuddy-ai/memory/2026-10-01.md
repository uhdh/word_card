## (13차) §2.23 (§5.2 35-B) — 기지 피격음이 적 피격에 **삼켜지지 않게** 했다

감독의 *"알아서 진행"* + 합의된 순서(**36 → 35 → 32 → 31**)에 따라 **35 (B)** 를 끝냈다.
36·31(A) 은 이미 완료(2026-09-26), 이번이 **35**.

### 결함 (감사 §2.23 · §5.2 35)

`DefenseField._on_enemy_reached_base()` 는 **바로 다음 줄 주석에서** *"기지 피격은 가장 강한
타격감이 필요한 순간"* 이라 적어 두고 그 등급을 **시각만** 받는다(흔들림 7.0 + 붉은 섬광).
소리는 `SoundEngine.play_hit()` — **적 피격과 같은 이름**이다. 그래서 둘.

1. **같은 파형** → 귀로 구별 불가(두 사건의 극성은 정반대인데).
2. ⚠️ **우선순위 역전** — 스로틀이 **이름별 50 ms** 라 적 피격이 먼저 났으면 기지 피격음은
   **나지 않는다**. 실측 `collision before=8 after_enemy_hit=9 after_base_hit=9` (+0).

### ⚠️ 핵심 판단 — 감사가 적은 (B) 의 *기구* 를 그대로 쓰면 안 된다

감사 §5.2 35 의 (B) 문구는 **"기지 피격을 스로틀 면제로"** 다. **그대로 구현하면 안 된다** —
면제하면 같은 프레임에 3마리가 도착할 때 소리가 **3회** 울려 `20*log10(3)` = **+9.5 dB** 가
되고, 소리의 세기를 *"그 순간 몇 마리가 도착했는가"* 가 정하게 된다. **그건 스로틀이 애초에
막으려던 것**(§2.12 유성 → 스로틀이 생긴 이유).

→ **스로틀 키와 파형 키를 분리**했다. 목표 둘을 **동시에** 만족하는 유일한 형태.

```gdscript
func _play_synth_stream(stream_name, generator_func, category_db := 0.0,
        throttle_key := "") -> void:
    ...
    var key := throttle_key if throttle_key != "" else stream_name   # 창만 나뉜다
func play_hit(throttle_key := "hit") -> void: _play_synth_stream("hit", ..., throttle_key)
func play_base_hit() -> void: play_hit("hit_base")   # 파형 키는 여전히 "hit"
```

⚠️ **일반화** — *"설명이 계약이다"* 가 여기서 **한 번 꺾인다**. 처방의 **목적**(우선순위 역전
제거)은 지키고 **기구**(면제)는 바꿨다. **계약은 문구가 아니라 목적에 걸려 있었다.**
→ 스킬 + 감사 §1.1 에 기록.

  다수 타격이라 확률이 과해질 수 있다"* 는 **분산**에 대한 우려인데, 선회는 원래 지속 피해라

### ⚠️ CRLF 왕복 함정 — 이번 세션의 가장 비싼 교훈

**파이썬 텍스트 모드 왕복(`io.open(p,'w')`)이 `TowerDefenseMain.gd` 의 CRLF 를 조용히 LF 로
바꿨다**(1659 CRLF → 0). 주입은 전부 성공했고 `RESTORE=True` 도 전부 참이었는데,
**그 참은 내용에 대한 것이고 바이트에 대한 것이 아니었다.**

- **왜 안 보였나**: `git config core.autocrlf=true` 라서 `git diff` 가 **경고만** 낸다.
  그리고 내 md5 자체 점검은 **변환 후에 뜬 스냅샷**과 비교하고 있었다 — 무의미했다.
- **무엇이 잡았나**: **더 오래된** 백업(`TowerDefenseMain.gd.bak`, 1622 CRLF)과 비교해
  줄바꿈을 세는 것. 그리고 `b.replace(b"\n", b"\r\n")` 로 **원래 md5 복원**.
- **규칙 둘**: ① 하네스는 **`rb`/`wb`** + **파일별 EOL** 로 앵커를 조립한다.
  ② **편집 후마다 CRLF 와 bare LF 를 세어 편집 전과 비교**한다(한 줄이면 된다).
- **실측 지도**: `scripts`+`tools` 의 `.gd` 중 **CRLF 10개**(`TowerDefenseMain`·`EnemyUnit`·
  `TowerOrbit`·`WordDatabase`·`LexiconModal`·`Shot`·`OrbitBalanceProbe`·`ShopReasonProbe`,
  그리고 **`MapManager`·`AutoPlayBot` 은 한 파일 안 혼합**). `WordTower`·`Meteor`·`DefenseField`
  ·`MonsterRoster` 는 LF.
- **`Edit` 도구는 안전하다** — `TowerOrbit.gd`(CRLF)를 편집해도 189→195 CRLF, bare LF 0.
  위험한 것은 **손으로 쓴 파이썬 하네스**뿐이다.
- 스킬 `godot4-project-workflow` 에 **"EOL trap 의 두 번째 얼굴"** 절과 파일별 표를 추가했고,
  프로젝트 MEMORY 에도 한 줄 넣었다(상한 8,000 자 — 7,975 로 맞췄다).

## (15차) §2.20 (C) 의 *근거* 가 거짓이었다 — 그리고 전파는 또 제목에서 멈췄다

### 잡은 것: 고치기 전 사본이 유일한 반증 수단이다

§2.20-7 의 (C) 기록은 *"길이만 줄이지 않고 **파형 종류**를 갈랐다(사인 vs `hit` 의 사각파)"*
라고 적고 있었다. **고치기 전 판을 열어 보니 둘 다 `sin()` 이었다.**

- `main/godot/scripts/core/SoundEngine.gd:137` (낡은 linked worktree) — 옛 `play_shield`:
  `duration = 0.16` · `freq = lerp(180.0, 340.0, …)` · `var s = sin(t * freq * TAU) * env * 0.45`
- 즉 (C) 가 실제로 바꾼 것은 **길이와 주파수 *방향*** 뿐이고, 파형 *종류* 차이는 **원래부터** 있었다.
- 그리고 `hit` 은 **사각파가 아니다** — `fmod(t*f,1)*2-1` = **톱니파**. 같은 파일이 `:476`·`:522`
  에서 이미 `톱니` 라고 적고 있었다. 셋(`SoundEngine.gd:176`·`:273`, 감사 `:1049`)을 톱니로 맞췄다.

⚠️ **거짓 근거는 재현이 불가능해서 오래 산다.** 길이·주파수는 지금 재면 되지만 *"무엇이
바뀌었는가"* 는 **고치기 전 판이 남아 있어야** 검증된다. 이번에 잡힌 것은 `main/` 사본 하나 때문.
**고침을 적을 때 되돌릴 수 있는 사본을 남겨라.** → 감사 §1.1 **아홉 번째** 구조적 발견으로 기록.
