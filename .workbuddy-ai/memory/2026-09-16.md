## ★ 회귀: 타일이 슬롯으로 드래그가 안 됨 (내가 만든 버그)

사용자 신고: "이번엔 타일이 슬롯으로 드래그가 안되."

### 원인
앞선 "선택이 잘 안 된다" 수정에서 `btn_tile.mouse_filter` 를
`MOUSE_FILTER_PASS` → `MOUSE_FILTER_STOP` 으로 바꾼 것이 원인.

Godot 4.7 에서 드래그 소스는 **마우스 포커스를 받은 컨트롤 하나만** 본다.
`PASS` 일 때는 이벤트가 부모로 전달돼 부모 `JamoTileBox` 가 드래그 소스가 되지만,
`STOP` 으로 바꾸면 엔진이 버튼만 보고 버튼에는 `_get_drag_data` 가 없으므로
**드래그가 아예 시작되지 않는다.** (`_get_drag_data` 자체가 호출되지 않음)

→ `PASS` 로 원복. 선택 문제는 `mouse_filter` 와 무관한 두 가지(회전 버튼 면적,
`button_down` 으로 누를 때 선택)로 이미 해결돼 있었으므로 둘 다 유지된다.

### 이 버그를 잡는 테스트를 새로 만들었다
`tests/test_belt_drag_drop.gd` + `.tscn` — **실제 엔진 입력 경로**로 재현한다.
`get_viewport().push_input()` 으로 마우스 press / motion(`button_mask` 필수) / release 를
흘려보내고, 타일→슬롯 이동과 타일→타일 순서 변경을 검증한다.
스크립트에서 `_drop_data` 를 직접 부르는 테스트로는 입력 라우팅 회귀를 못 잡는다.

**⚠️ 이 테스트는 반드시 창을 띄워서 실행해야 한다.**
`--headless` 에서는 GUI 히트테스트가 동작하지 않아(`gui_get_hovered_control()` 이 null,
`button_down` 이 아예 안 옴) 자동으로 SKIP 한다.
(디버깅 중 headless 로 실패해서 한참 헤맸다 — headless 실패는 하네스 한계이지 게임 버그가 아니다.)

## 후속 신고 3건 (타워 이동 / 이중 테두리 / 선택 불가)

사용자 신고: "타워 이동이 안되. 그리고 타일이 이중 테두리가 있고, 잘 선택이 안되"

### A. 타워 이동이 안 되던 원인 3가지
1. **웨이브 중 이동 금지** — `DefenseField.move_tower()` 가
   `if is_wave_running and not is_planning_phase: return false` 로 막고 있었다.
   `is_planning_phase` 는 15초마다 잠깐만 열리므로 사실상 이동 불가.
   → 게이트 제거. 현대 TD 처럼 **언제든 재배치** 가능.
2. **`_was_dragged` 래치 버그** — `WordTower` 에서 이 플래그를 `Button.pressed`
   콜백에서만 풀었다. 드래그가 버튼 밖에서 끝나면 `pressed` 가 오지 않아
   플래그가 true 로 남고, **이후 첫 클릭이 계속 씹혔다.**
   → `pressed` 연결을 아예 제거하고 `gui_input` 하나에서 클릭/드래그를 모두 처리.
3. **드래그 상태 미초기화** — `_dragging` 이 release 를 놓치면 true 로 남아
   버튼을 누르지 않아도 타워가 마우스를 따라갔다.
   → release 에서 항상 초기화.

`WordTower.gd` 를 `begin_drag/update_drag/end_drag(at: Vector2)` 로 분리해
좌표를 직접 넣어 테스트할 수 있게 했다. 드래그 중에는 `z_index=60` + 밝기로 띄운다.

### B. 타일 이중 테두리
`JamoTileBox`(PanelContainer, 기본 테마 테두리) + `btn_tile`(자체 StyleBoxFlat 테두리)가
겹쳐 두 겹으로 보였다.
→ `JamoTileBox` 에 `StyleBoxEmpty` 를 씌워 **테두리는 버튼 하나만** 그린다.
   포커스 링(`focus` 스타일)도 `StyleBoxEmpty` 로 제거 (세 번째 테두리 원인).

### C. 타일 선택이 잘 안 되던 원인 2가지
1. **회전 버튼이 타일의 28%를 먹었다** — 64x62 타일 우하단에 34x34 STOP 버튼.
   → 26x26 으로 줄이고 진짜 모서리로 이동 (우하단 사분면 안에만 머물게).
     배지도 16x16 으로 줄여 테두리 안쪽으로 넣었다.
2. **엔진 드래그 판정이 클릭을 취소** — Godot 는 10px 만 움직여도 드래그로 판정해
   `Button.pressed` 자체를 보내지 않는다. `Button.pressed`(놓을 때) 로 선택하던 구조라
   클릭이 통째로 취소됐다.
   → **`button_down`(누를 때) 로 선택**하도록 변경.
   - 단, 선택만 바뀔 때는 `render_belt()` 로 트리를 재생성하면 안 된다
     (누르고 있던 버튼이 트리에서 빠지면 드래그가 시작되지 않는다).
   - 그래서 `_refresh_tile_selection()` 을 새로 만들어 **스타일만** 갱신한다.
     실제 데이터 변경(교체/스왑)일 때만 `render_belt()`.
   - 드래그가 시작되면 `_get_drag_data` 에서 선택을 해제하고 표시도 되돌린다.
   - 선택 표시는 `modulate`(금색 틴트) 대신 **금색 테두리 + 밝은 배경**으로 명확하게.

### 시도했다가 되돌린 것
`project.godot` 에 `gui/common/drag_threshold=18` 을 넣어 드래그 판정을 둔하게
하려 했으나 **엔진이 시작할 때 무조건 10 으로 되돌린다**(직접 실측 확인).
같은 섹션의 임의 키(`common/test_probe=42`)는 정상 로드되므로 파일 파싱 문제가 아니라
해당 설정이 런타임에 강제되는 것. → 프로젝트 설정은 원복하고 코드로 해결했다.

# 추가 작업 — 타워 비주얼 · 새 공격 방식 · 골드 밸런스

사용자 요청:
"타워가 검은 배경이 있는데 배경을 제거하고 크기를 더 크게. 타워의 공격 형식을 더 다양하게
(뱀파이어 서바이버처럼 주위를 맴도는 성경책, 랜덤하게 떨어지는 메테오). 골드가 너무 많아."

## (a) 타워 카드 — 검은 배경 제거 + 확대

- 원인: `WordTower._apply_visual_style()` 이 `StyleBoxFlat.bg_color` 를
  `Color(0.12,0.10,0.18, 1.0)` (거의 불투명) 으로 덮고 있었다. tscn 값만 봐선 안 보인다.
- 해결: `bg_color = Color(0,0,0,0)`. 대비는 세 가지가 만든다.
  1. 카테고리 색 **원형 링** — `corner_radius = 한 변의 절반` 이면 둥근 사각형이 아니라
     **완전한 원**이 된다(트릭). 3px.
  2. `_draw()` 의 **라디얼 소켓** — 같은 중심의 반투명 원을 12겹 겹쳐 그려
     가운데만 살짝 어둡게. `StyleBoxFlat` 은 라디얼 그라데이션을 못 그려서 직접 그린다.
     반지름 30px 로 링(38)보다 작게 잡아 가장자리는 비워 둔다.
  3. 검은 그림자(`shadow_size=2`) — 밝은 정원 맵에서도 떠 보이게.
- 크기: 64 → **76px** (반지름 38), 아이콘 36 → **52**.
  상한은 `DefenseField.PAD_RADIUS(32) + PAD_ROAD_GAP(8) = 40` 이고
  `VISUAL_RADIUS(38) + SHADOW_REACH(2) = 40` 으로 딱 맞췄다.
  → **발판(PAD_RADIUS)은 그대로 두고 타워 시각만 키웠다.** 발판을 키우면
    `need` 가 커져 발판이 길에서 멀어지고(=사거리 밖) 게임플레이가 나빠진다.
  - 이 관계를 `TestLoreModal.gd` 가 검증한다.

### ⚠️ 여기서 잡은 함정

→ `nature→splash` 로 재배치하고, `_test_every_boss_weakness_is_reachable()` 로 고정.

### ⚠️ Godot 함정: 새 `class_name` 은 에디터 스캔이 필요하다

등록되기 전에는 다른 스크립트에서 못 찾는다:
`Parse Error: Could not find type "TowerOrbit" in the current scope.`

(게임을 그냥 실행하는 것만으로는 안 됐다.)

## (13) 시그널 인자 스냅샷 버그 — 1막 클리어가 2막으로 보고되던 문제

`tools/EconomyPlaytest` 를 3막 완주로 돌렸더니 표가 이상했다: 라운드 20 이 아예 없고,
라운드 40 에서 `구매 14장`(35라운드의 23장보다 **작다**). 구매 수는 단조 증가라 불가능.

추적 결과 **Godot 4.7.2 실측 엔진 동작**을 확인했다:

> 시그널 인자로 **멤버 변수를 그대로** 넘기면 emit 시점에 스냅샷되지 않는다.
> 앞선 핸들러가 그 멤버를 바꾸면, 뒤 핸들러는 **바뀐 값**을 받는다.

```gdscript
signal sig(a: int, b: int)
var member := 1
sig.emit(member, 8)   # 핸들러1: a=1 (그리고 member=2 로 변경), 핸들러2: a=2  ❌
var snap := member
sig.emit(snap, 8)     # 핸들러1: a=1, 핸들러2: a=1  ✅
```
(지역 변수에 담거나 `member + 0` 같은 식으로 만들면 정상.)

원인 지점: `DefenseField._grant_round_reward()` 의 `act_cleared.emit(current_act, ...)`.
첫 리스너 `TowerDefenseMain._on_act_cleared` 가 `_start_wave_automatically()` →
`start_next_wave()` 로 `current_act` 를 올려버려서, **그 뒤에 붙은 리스너는 1막 클리어를
2막으로 받았다.** 게임 UI 자체는 첫 리스너라 정상이었고(플레이어 피해 없음),
진단 도구만 오염됐다. `act_cleared` / `wave_cleared` 둘 다 지역 변수로 스냅샷하도록 수정.

곁들여 알아낸 것:
- **람다는 지역 변수를 값으로 캡처한다.** 람다 안에서 바깥 지역 변수에 대입해도 안 바뀐다.
  결과를 받으려면 `Array`/`Dictionary` 같은 참조 타입을 써야 한다.
- **지연 람다가 노드를 캡처하면 그 노드가 먼저 죽을 때 터진다.**
  `create_timer(3.0).timeout.connect(func(): if is_instance_valid(modal): ...)` 도
  `Lambda capture at index 0 was freed` 가 난다 — `is_instance_valid` 는 캡처 바인딩
  *이후*에 돌아서 이미 늦다. `WeakRef` 로 잡아야 한다. `Juice.shake()` 리셋 콜백과
  막 클리어 모달 자동 닫기에 적용.
- `weakref()` 반환형이 Variant 라 `var r := weakref(x)` 는 이 프로젝트에서 에러다
  (경고=에러 설정). `var r: WeakRef = weakref(x)` 로 명시할 것.
- `--check-only --script` 는 오토로드를 안 실어서 `SoundEngine` 류가
  `Identifier not found` 로 거짓 보고된다. 단일 파일 문법 검사용으로만 쓸 것.
- **같은 파일에 Edit 를 한 메시지에 두 번 보내면 서로 덮어쓴다.** 하나씩 적용할 것.

## (15) 활자 교체(타일 리롤) — 포화 이후 골드 소비처 추가

(14)에서 병목이 '가격'이 아니라 '벨트 상한 30장'으로 밝혀져, 사용자가 **반복 소비처 추가**를 선택.

**구현**
- `JamoBelt`: `tile_swap_requested(index)` 시그널, `swap_tile_button`, `swap_mode`,
  `current_swap_price()`, `swap_jamo(index, new_char)`.
  기존 `타일 제거` 의 '모드 켜고 → 타일 클릭' 패턴을 그대로 따랐다.
  **제거 모드와 교체 모드는 서로 배타적** — 둘 다 켜지면 타일 클릭 의미가 모호해진다.
- `TowerDefenseMain._on_tile_swap_requested(index)`: 골드 차감 → `register_tile_purchase()`
  → `swap_jamo()` → 저장. **같은 종류(자음/모음) 풀 안에서만** 바꾼다
  (벨트의 자음·모음 구성 유지). 같은 활자가 나오면 돈을 받지 않는다.
- 이름은 **'활자 교체'** 로 정했다. `reroll_dice`(웨이브 보상 새로고침 주사위)가 이미
  있어서 '리롤' 이라는 말이 겹친다.

**설계 근거 — 교체도 시장 거래로 친다**
교체 값을 `current_tile_price()` 로 두고, 교체할 때도 `register_tile_purchase()` 를 부른다.
값이 싼 동안(초반 10G) 무한정 돌려 완벽한 벨트를 만드는 것을 막는 장치다.
대신 교체를 많이 하면 구매 시세도 같이 오른다 — 시장이 하나라는 일관된 규칙.
